## 八、已知坑与解法（工程经验，省你重踩）
- github.com:443 常不可达：git push 不可用→走 `temp2/work/apipush.py`（Git Data API；恰好 6 个位置参数；PR 创建 422 "already exists" 多为响应超时假象，gh pr list 确认）。
- 多行 shell 字符串手术易咬错位置：改用整文件重写+机器断言（grep 计数）再推。
- workflow 内 python：取 GitHub 文件必须 `Accept: application/vnd.github.raw`；非 JSON 资源 expect_json=False；cd repo 后相对路径是 `../x` 不是 `../stage/x`；`python3 -u`；GIT_TERMINAL_PROMPT=0；CNB git 认证 username 固定 `cnb`。
- CNB：建仓端点 POST /{org}/-/repos（body: name/visibility/description）；服务端 hook 禁推 refs/pull/*；`.github` 仓在 CNB 须命名 `github-mirror`。
- gitcode API：PRIVATE-TOKEN header（非 query 参数）；push 用户名=账号名。
- PG from gen-sqlddl：DATETIME→TIMESTAMP×39+前向 FK 需补丁（SEL-01-ddl-patch.sql 可重放）。
- OpenBao dev=inmem：重启失态（生产切文件存储=服务器阶段首批）。
