## T-01 真值区平台 —— 收缩为断裂裁决的从属项

**现状事实**：ADR-0020 全仓公开政策已裁决"组织无私有仓"；TOOLING T-01 预设的"自部署 vs 云私有仓"权衡被该政策**抢占了前提**。

**新增证据（GitHub 条款，与 T-02 共用）**：GitHub 服务条款（2026-04-27 生效版）——

> D.4（原文大意，已核对 [docs.github.com ToS](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)）：用户授予 GitHub 与其关联公司存储、托管、存档、解析、显示及制作副本的权利，**包括训练 AI 功能与训练/开发 AI/机器学习模型与技术**。
> E.3：GitHub 承诺**不将私有仓内容用于开发或改进服务**，除非作为 AI 功能输入提供（可经 J.3 关闭）；私有仓内容视为机密（法律要求/安全扫描等例外除外）。

**对否决项①（条款不得索取训练权）的读数**：GitHub **公开仓不合格**（D.4 明示训练权）——这正是 FR-01 的证据面；GitHub **私有仓在 opt-out AI 功能输入的前提下可通过**否决项①。自部署方案（Gitea/Forgejo）训练权为零，通过。

**处置建议（S5 裁决框架）**：本任务不再独立裁决——T-01 的答案由 FR-01 的裁决派生：
- FR-01 选 A/C（维持公开/混合）→ T-01 结论="不采购"，登记退役条目（理由：政策抢占，引用 ADR-0020+FR-01）；
- FR-01 选 B（建最小真值区）→ 启动子任务：GitHub 私有仓（零迁移、opt-out、计费观察条款——ADR-0096 已登记删除重建禁令）vs 自部署 Forgejo（运维分钟数直接消耗 S5 时间，TOOLING T-01 原警告继续有效）。**倾向证据**：一人组织运维预算下，GitHub 私有仓+密文化答案层（T-10）组合的退出成本最低。

| 对象存储（R2/COS/OSS） | ✅ | 免费额度各异 | S3 API，bundle push 即可 | ✅ 通过（形态：对象非代码托管） | 【未测】 |

**组合建议（证据支持的对比，非决定）**：
- **候选一：CNB + Codeberg**——地理/法域/运营主体三重独立；CNB 零新增凭据面（复用 org secret CNB_TOKEN_*）；Codeberg 补足中国境外的第二法域。风险：CNB 免费配额"随时可能收紧"（cnb-bridge 自报）——但镜像只读、可整层删除（可删除层纪律），失效模式温和。
- **候选二：CNB + Gitee**——全境内双镜像，网络可达性最好；劣势：两平台同为境内主体，法域独立性弱于候选一。
- 密文化使"私有仓 ≤5 成员/100MB"等限制不敏感（镜像=加密 bundle，只读，无协作）。

**同步与对账设计（草案，沿用 GM-1 模式）**：weekly `git bundle --all` → age 加密（T-10）→ push 两平台 → 対账引擎逐平台校验（bundle 完整性 `git bundle verify` + 大小/哈希对账，链断=红）→ evidence 账本落一行；季度恢复演练（随机 bundle 解密重建裸仓 + `git fsck` + 抽样 blob 比对）——MIG W2 门禁③"从镜像实际恢复一次"思想原样继承。
**试用期 spec 草案**：spec=镜像仓位置/加密格式/push 节律/对账谓词；eval=注入演练（删一个镜像→对账红→恢复→绿）；退出条件=连续 2 周对账零漂移+1 次完整恢复演练通过。
**登记簿草稿**：R-02（试用中）。

## T-09 控制面数据层 —— "不采购"建议（负结果登记）

**既有事实**：控制面数据层=git（append-only 由规则集+drift 对账执法）+JSONL hash 链账本（判定层 archive/evidence）+GitHub ref（租约/防重放台账，arbiter 用 Git refs 做原子 CAS）——**无任何数据库**。

**建议**：**不采购 DB**，登记负结果条目（"控制面数据层在此用途上不需要 DB"——条件：单写者低频 append、规模 ≤ 千级卡/月、查询=evidence-query.sh 归并即可）。**复活条件登记**（STRAT §7.2 过期条件思想）：跨仓复杂联查成为月频需求 / 事件量使 JSONL 归并超分钟级 / 多租户 tenant 聚合需要索引时，重启选型（届时 PostgreSQL 审计形态为默认候选）。R-07。

| **age** | `age-encryption.org/v1` 稳定规范，多独立实现（Go/Rust rage/C agec）；近期增后量子 recipient（mlkem768x25519） | SOPS 后端、agenix 等；小显式密钥、零配置 | Go 生态与 selfcloud 同栈；`age -r <pubkey>` 流水线一行 | ✅ [github.com/FiloSottile/age](https://github.com/FiloSottile/age) 核对 |
| GPG | 30 年格式稳定 | 最广 | 复杂度高（keyring 管理），DGA"十年后仍可解密"稳但运维重 | 常识+【未测】 |
| git-crypt | 透明加密进 repo | 维护活跃度低【待核】 | 与 bundle 镜像方案不匹配（密文应在镜像侧） | ◐ |
| rclone crypt | 对象存储同步加密 | 成熟 | 若镜像走对象存储则优于 age；走代码托管则 age 更直接 | 【未测】 |

**TOOLING 否决项核对**：①密钥不出真值区——age 私钥入 org secret（INV-04 现有纪律）+公钥入仓（attest-pub.pub 先例：CIW keys/ 公钥入仓、私钥入 secret，W4-R3 已跑通同款模式）；②长期可读性——age v1 规范固定+多实现，满足"十年后仍可解密"纪律；GPG 为对冲备份格式可并行登记（镜像双格式 bundle 成本=一条命令）。
**密钥管理 S5 边界裁决材料**（TOOLING T-10 要求的对比）：org secret（现有面、已执法、GitHub 依赖+1）vs 内网 Vault（已入图、执行面分域、跨域取钥增加镜像流水线一跳）——**现状证据**：attest 签名密钥走 org secret 先例 + Vault 零 org secret 分域设计，两者都是既定架构的合法延伸，倾向证据各半，**维持 S5 裁决不做建议**。
**试用期 spec 草案**：spec=age v1、公钥入 CIW keys/、私钥入 org secret `BACKUP_AGE_KEY`；eval=注入演练（篡改 bundle → verify 红；密钥错误 → 解密红；正控双格式互验绿）；退出=与 T-03 试用期合并验收。
**登记簿草稿**：R-08（试用中，先决于 R-02）。
