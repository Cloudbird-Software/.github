## 第 0 章 建设公理（两条新增推导层原则）

### PR-INF-01 企业级复刻即资产

一人公司采用企业客户同款组件栈进行全量建设，不是成本错配，是判定资产的复利投资：

a) [RULE-05] 的工程化：治理产品的信用抵押物 = "本公司运行时的栈 = 客户可复刻的栈"。A 类客户（国企/政府）的信任判据是"你自己怎么跑的"，答案必须是企业级栈。
b) 全量建设的配置、IaC、runbook、故障演练记录 = 可交付的 spec 工件，直接构成 PROD-05（能力转移）的参考实现。
c) 企业组件的运维负担是执行成本（可 agent 化、廉价）；其复刻价值是判定资产（稀缺）。选型时两者相权，资产侧优先。
d) 一人跑通企业级栈本身是 [LAW-01] 变异度放大器的活证明：治理通过 agent 化实现，不通过人力实现。
e) 由此产生的选型硬约束：每个组件必须通过"客户可复刻"检查（见 8.4 的四问）。

### PR-INF-02 资源池化即治理

多来源、多账号、多付费级别的资源池化统一调度，是治理能力与产品资产，不是省钱 workaround：

a) 客户环境天然异构：多供应商、多期采购、配额不均、可靠性参差。本公司运行在池上 = 治理栈在客户环境仿真条件下的持续 soak test。
b) 池调度器（路由/降级/配额/信任标签/熔断）本身是 DGA 资源治理的参考实现，未来可产品化输出。
c) 池组成是被监控的分布参数（[LAW-04] 细化）：校准的有效域 = 池组成的声明快照；池组成变化触发漂移重估。判定能力建模的是池混合分布，不是单端点。
d) 免费层 + 付费层 + 多账号的混合是显式的价值获取策略；其风险（TOS 合规、数据隐私、产能波动）不假装不存在，而是显式化、标签化、路由化。
e) 客户本地部署（[DER-11]）时，客户自带的 key 与算力通过同一池抽象接入——"资源池"是外部资源的一等公民接口。

**修正声明（记录在案）**：本文档推翻此前非正式建议中的三点——① Temporal 轻量化替代方案（改为全量建设）；② OPA 内嵌代码替代方案（改为全量建设）；③ 判定仪器绑定单模型的二分法（改为校准域声明制）。

## 第 3 章 资源池化体系（本文档的核心新增）

### 3.1 池对象模型

```
ResourcePool（资源池账本，权威源=控制面 DB）
├── Provider: anthropic / google / deepseek / openai / cloudflare / railway / ...
├── Account: 一个 Provider 可多账号
│    ├── credential_ref    # 凭据引用（明文在凭据库，此处仅引用）
│    ├── cost_tier         # free / low-paid / high-paid / enterprise
│    ├── quota_state       # RPM / TPM / 日额 / 月额 / 信用池余量
│    ├── trust_label       # T0 / T1 / T2（见 3.2）
│    ├── tos_risk          # 合规风险标签（见 3.6）
│    └── health            # 可用性 / 延迟 / 错误率 / 最近故障
├── LogicalEndpoint: 逻辑端点名（如 free-workhorse / paid-judge / t1-only）
│    └── 绑定 Account 集合 + 路由策略
└── RoutingPolicy: 按能力/成本/信任/配额/漂移约束路由
```

每个池对象是资产目录中的正式资产：有稳定 ID、具名责任人、健康度量、验证时间、退役方式。

### 3.2 信任标签路由（R-POOL-TRUST）

端点带 trust 标签，任务带 sensitivity 标签，路由规则：任务 sensitivity ≤ 端点 trust。

| 端点级 | 定义 | 允许处理的数据 |
|---|---|---|
| T0 | 免费层 / 个人订阅账号（TOS 下供应商可能用数据训练，产能无保障） | 仅公开数据、内部低敏任务、合成测试数据 |
| T1 | 付费 API（合同明确数据不用途、产能有 SLA） | 一般客户业务数据 |
| T2 | 企业级端点 / zero-retention / 客户指定端点 | 敏感客户数据、判定仪器运行 |

这是 [DER-03]（MCP×Harness 成对律）在资源层的实现：池路由就是资源层的 harness。

### 3.3 数据红线（R-POOL-DATA，硬红线）

客户业务数据禁止路由至 T0 端点。例外仅当：合同显式允许 + 数据已脱敏至证据级。违反此线 = [RULE-02] 级别的违规（本体资产风险）。

### 3.4 TOS 合规审计（R-POOL-COMPLIANCE）

每个 Provider 出具 TOS 风险矩阵：多账号条款、免费层用途限制、数据使用条款、个人订阅转 API 使用的许可度。多付费个人账号轮换（S5 认可的价值获取策略）按风险矩阵处理：不禁止、不默认，风险显式标注，个人账号一律打 T0 标签（产能波动容忍 + 内部低敏专用），TOS 灰区的接受范围由 S5 裁决。Agent 不得自行判定 TOS 灰区可否使用；发现灰区即升级。

### 3.5 降级链（R-POOL-DEGRADE）

T1 主力付费 → T1 备用付费 → 低成本付费 → [队列等待 / 任务挂起] → 升级 S5。免费层（T0）只承接 T0 任务，不作为任何客户链路的降级终点。禁止自动跳到 S5 未批准的成本等级。等待超过闭环授权的决断时距 → 挂起 [MET-01]。

### 3.6 成本熔断（R-POOL-BUDGET）

闭环级预算上限（capability policy 声明）；全司日熔断 / 月熔断（超限自动全局降级或挂起，通知 S5）；熔断事件本身入证据流——成本维度的爆炸半径控制。

### 3.7 配额账本校准（R-POOL-QUOTA）

账本记录的用量 vs 供应商面板实际用量，定期抽查，误差超阈值报警。池自身是一个六元组闭环单元：有 spec（路由策略）、eval（配额准确性/故障转移时延/错误率）、证据（调度日志）、责任人（S5）。池的度量进入治理度量体系。

### 3.8 校准域声明制（R-POOL-CALIB，理论修正的落点）

上轮"判定绑定单模型"作废。新构造：

- 每份 eval 校准必须声明其校准域：覆盖的模型集合（池组成快照）+ Spec/Harness 版本 + 观察窗口。
- 池组成变化（新增/移除/权重调整被校准域覆盖的模型）⇒ 触发相关闭环的漂移重估工作流——不是禁止漂移，而是把漂移纳入治理。
- 每次判定运行的证据必须包含：判定器模型 + 版本 + 校准域 ID。

这条作为 [LAW-04] 的工程化细化，待并入 DGA-CORE 下一版：评估器建模的是池混合分布，池组成是显式监控的分布参数。

### 3.9 池健康证据（R-POOL-EVID）

故障转移时延、端点错误率、配额误差、熔断触发次数——池的运行度量进入狗狗公示仪表（[RULE-05] 的资产展示："本公司在异构资源池上维持判定质量"本身就是对客户的证明）。

### 3.10 产品化映射（池能力 → 客户场景）

| 池能力 | 客户场景 |
|---|---|
| Provider 抽象 + 信任标签路由 | A 类：国产化多供应商环境、合规路由 |
| 成本分层 + 降级链 | C 类：成本敏感、预算约束 |
| 小配额池管理 | B 类：OPC 资源约束识别 |
| 外部资源接入池抽象 | 客户本地部署自带 key/算力（[DER-11]） |
| TOS 风险矩阵 | 治理咨询的合规模块素材 |

## 第 5 章 建设要求总表（R 系列）

### R-GOV 治理结构

- R-GOV-01 关键字段唯一权威源（第 1 章表）；多入口不允许多主写者。
- R-GOV-02 每个闭环的六元组绑定进 Git（稳定定义）与运行时（动态值）分离。
- R-GOV-03 新闭环缺具名责任人 ⇒ 拒绝生产执行资格 [LAW-03]。
- R-GOV-04 S5 决策卡片固定结构：对象/证据/选项/推荐/期限/批准后果。
- R-GOV-05 项目（有限期变更）与服务（持续履约）分离登记；项目完成 ≠ 责任消失。
- R-GOV-06 新增 S5 决策量 × 平均审阅时间 < 可投入时间，留余量；超限收缩并行承诺 [LAW-02]。
- R-GOV-07 S5 不可用时：高风险写停止，进入事先批准的只读/缓存/排队/安全停止模式；禁止"贴 L1 标签创造审核能力"。

### R-FLOW 流程（Temporal）

- R-FLOW-01 跨系统、跨天、含人类等待的流程一律进 Temporal；Agent 会话不承载等待。
- R-FLOW-02 每个有外部副作用的步骤，唯一重试责任方；结果不明进"待核实"，禁止盲目重发。
- R-FLOW-03 幂等键 + 结果核对 + 补偿；Temporal 语义不默认保证恰好一次。
- R-FLOW-04 崩溃恢复后可区分：已发生/未发生/不确定的副作用。

### R-POL 策略（OPA）

- R-POL-01 权限检查在工具网关/服务端强制执行；"模型被告知不能做"不算权限控制。
- R-POL-02 子任务权限 ≤ 父任务；拆十个 agent 不获得十倍预算；重建 Run 不得延长无人复核期限；恢复检查点须重验当前授权。
- R-POL-03 池路由的虚拟 key 限额落实 R-POL-02（每个执行单元独立限额 key）。
- R-POL-04 执行者不能修改验收标准、校准参数、已记录失败；换模型评审 ≠ 获得校准判定 [LAW-04]。
- R-POL-05 OPA decision log 入证据流（策略判定记录 = 证据的一等公民）。

### R-POOL 资源池（第 3 章全部）

R-POOL-TRUST / R-POOL-DATA / R-POOL-COMPLIANCE / R-POOL-DEGRADE / R-POOL-BUDGET / R-POOL-QUOTA / R-POOL-CALIB / R-POOL-EVID，共八条，正文见第 3 章。

### R-EVID 证据

- R-EVID-01 证据契约独立定义（执行收据/验收判定/签发记录/校准资产的结构）。
- R-EVID-02 Trace ≠ Evidence；评估界面 ≠ 校准能力。
- R-EVID-03 重要证据：对象版本 + 内容摘要 + 独立写入权限 + 对象锁定；防篡改证明"记录未被改"，不证明"记录为真"——仍需独立探针/外部收据/客户确认。
- R-EVID-04 判定证据必须含判定器模型+版本+校准域 ID（R-POOL-CALIB）。
- R-EVID-05 证据缺失是治理异常，与业务失败/结果不确定/判定器失效区分登记；没有失败证据 ≠ 成功。

### R-SEC 身份与凭据

- R-SEC-01 Agent 接 GitHub 用应用身份；CI 访问云用 OIDC 短期凭证；禁止个人万能 Token 复制给执行者。
- R-SEC-02 凭证明文仅存凭据库；控制面/Git/飞书仅存引用。
- R-SEC-03 池账号凭据轮换有 runbook 与撤销验证。
- R-SEC-04 Agent 不能通过 API、共享凭证或重放旧批准完成代签 [RULE-04]。

### R-IR 恢复与迁移

- R-IR-01 暂停 = 撤销执行租约 + 阻断工具调用 + 停止派发 + 处理在途动作；"停止对话"不算。
- R-IR-02 回滚不能只恢复数据库备份；外部已发生动作不随 DB 回滚消失，须保留动作收据核对。
- R-IR-03 新旧系统切换用影子运行 + 单写切换；排空旧任务、撤销旧凭证、验证旧入口不能再写。
- R-IR-04 历史证据不足的项目标记"治理状态未知/待验证"，不因 CI 好而继承 L3。

### R-CFG 配置

- R-CFG-01 治理配置仓库结构按第 4 章。
- R-CFG-02 存量处置四分类：继续运营（先加治理外壳）/整改/抽取资产/归档退役。
- R-CFG-03 现状行为、历史意图、当前批准的目标行为三者分开登记；不从旧代码反推 Spec。

### R-OBS 观测

- R-OBS-01 全链路 OpenTelemetry；Langfuse 管评估工作台。
- R-OBS-02 治理度量自动化进公示仪表（[RULE-05] 狗粮公示的工程化），含池健康度量。
- R-OBS-03 验证比计量固定口径（分子含客户验证时间与事后复核；分母为业务定义可信产出；返工/迟发失败不消失；[BAN-06] Goodhart 防护）。

## 第 6 章 建设里程碑（纵向切片：架构不缩水，分期的是范围）

原则：M3 起每个里程碑都是一次全架构贯穿（飞书入口 → 控制面 → 流程 → 执行 → 证据落盘），范围递增。

| M | 内容 | 验收要点 |
|---|---|---|
| M0 | 对象模型/ID/权威源/决策点定稿（schemas 仓库） | 六元组 schema、权威源表、S5 裁决清单可评审 |
| M1 | 控制面 v0（PG+核心表+闭环注册+S5 队列）+ 飞书四工作台 | 一个手动闭环全登记；缺责任人的闭环被拒绝创建 |
| M2 | 资源池 v0：LiteLLM + 池账本 + 凭据库 + 降级链 | T0/T1 标签生效：敏感任务被 T0 端点拒绝；配额账本可查 |
| M3 | Temporal 全量上线 + 第一条真实流程（客户反馈→修复→CI/Eval→发布→验收→校准提案） | 跨天等待不依赖会话；崩溃恢复无重复副作用 |
| M4 | OPA 全量 + 工具网关 + decision log 入证据 | 越权调用被真实拒绝（非提示词级）；判定记录可追溯 |
| M5 | 执行单元多环境：Harness 接池 + ≥2 个执行环境 + 检查点外置 | 换执行环境不丢业务状态；虚拟 key 限额生效 |
| M6 | 证据层：证据契约 + OTel/Langfuse + 对象存储版本锁定 | 判定证据含判定器版本+校准域 ID；对象锁定验证 |
| M7 | 池治理完善：池组成变更→漂移重估工作流；成本熔断；时距到期自动挂起 | 人为注入池变更触发重估；注入超预算触发熔断 |
| M8 | 验收套件：第 7 章全部负面测试 + 故障演练 | 撤权/崩溃/证据缺失/S5 离线/池故障五类演练通过 |
| M9 | 公示仪表 + 治理度量自动化（含池健康） | 狗粮公示上线；度量口径经 Goodhart 防护审计 |

OpenJiuwen（CMP-04）：定位核实后插入 M4–M7 之间合适位置，由 SEL-04 输出集成方案。

## 第 7 章 验收矩阵（负面测试优先——测坏情况，不测正常流程）

**治理十项**（继承专家提案，全文有效）：责任完整性 / 版本与前提可追溯 / 工具权限真实强制 / 自治边界到期即停 / 判定隔离 / 恢复与幂等 / 遥测与租户隔离 / S5 签发不可代 / 公示完整性 / 退出与恢复。

**池化七项**（本版新增）：

| 验收项 | 必须证明 |
|---|---|
| 池故障转移 | 主端点 429/宕机 ⇒ 路由切换，闭环不中断，事件入证据 |
| 配额准确 | 账本 vs 供应商面板抽查误差 < 阈值 |
| 成本熔断 | 注入超预算运行 ⇒ 自动降级/挂起 + 通知 |
| TOS 审计 | 账号池全量有 TOS 风险标签；灰区账号被隔离于 T0 |

| 校准域 | 池组成变化事件触发漂移重估工作流 |
| 判定溯源 | 抽任一历史判定可还原：判定器模型+版本+校准域 |

### 8.4 调研纪律

- 禁止凭模型记忆断言任何具体数字（版本号、价格、配额、功能支持状态）。一切事实标注来源 + 核实日期。本文档中 2026-09 出现的参数均为快照，选型 agent 必须重新核实——包括"Gemini 免费层 60 RPM""Temporal 支持 Postgres"这类陈述。
- 许可证必须查 LICENSE 原文，不得引用二手描述。
- 客户可复刻四问（每个候选必须回答）：① 客户能否合法部署该组件（许可证）？② 是否有客户可用的部署文档与单机起步路径？③ 是否存在强制性云绑定或供应商锁定？④ 复刻时哪些功能会缺失（开源/企业分界）？
- TOS 类发现（灰区、变更、风险）一律升级 S5，agent 不做可否判断。
- 重大选型先 PoC + 至少一项负面测试，再定。

### 8.5 升级触发

规格空白（本文档未覆盖的决策点）⇒ 升级 S5 [APT-07 继承]；调研中发现与 DGA-CORE 冲突 ⇒ 停止执行，出冲突报告。
